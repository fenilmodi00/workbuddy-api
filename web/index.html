First-time admin Key setup

The server will generate a random 32-character admin Key, write it to config.json, and show it in a popup only once after this operation completes. Please store it safely.

Two ways to set it up: ① open this page on the server itself (or via SSH local port forwarding) and generate a random 32-character Key with one click; ② edit config.json directly on the server, set gateway.adminKey to a random string, and it takes effect about 1 second after saving. Automatic generation is limited to the local machine to prevent a remote host from initializing first; once set up, you can log in from other devices with the admin Key.

Accounts

Scheduling toggles are written to models.accounts.all.blocklist and take effect immediately. If a global allowlist exists, the first toggle removes all.allowlist and converts the current pool on/off states into a blocklist; accounts added afterwards default to enabled. Disabling does not delete credentials, clear ledgers, or interrupt running requests; when enabled, accounts still follow model-specific rules.

Credentials are written directly into the program's working directory; no manual file placement needed.

Log retention and cleanup

0 keeps everything; 7 keeps today plus the previous 6 days. Saving writes config.json and automatically cleans up expired logs; deletion is irreversible. Only project logs are handled; config and credentials are never deleted.

Saving is equivalent to editing the server's config.json directly. Preview always hides keys; the raw content with real keys loads only after you acknowledge the edit warning.

Confirm the risks before editing

  • This is the entire server configuration, not a copy. The editor shows real admin and API keys; do not share screenshots or edit on public devices. Access only over a trusted network, HTTPS, or SSH forwarding, and back it up yourself first.
  • After saving, keys, model/account rules, prompts, and listening ports hot-reload immediately; existing connections and streaming requests are not actively interrupted. The API port may still be overridden by the -port startup flag.
  • Changing the admin Key requires logging in again; clearing it disables admin login until it is reset on the server itself.
  • Changing log retention may trigger deletion of expired logs, which is irreversible. Invalid config is rejected and never written to the file.
